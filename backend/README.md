# Industrial Fire & Thermal Source Classification — Backend

Backend for **SIH26162** (NTRO). Ingests NASA FIRMS hot-spot data, matches
each detection to known industrial facilities (OSM), classifies it into
`gas_flare / accident_explosion / crop_burning / coal_seam_fire / wildfire /
desert_glare_false_alarm`, and raises alerts for genuinely abnormal events.

## Stack
- **FastAPI** — REST API
- **PostgreSQL + PostGIS** — spatial storage + spatial joins (ST_DWithin, ST_Distance)
- **SQLAlchemy + GeoAlchemy2** — ORM with geometry columns
- **APScheduler** — periodic FIRMS/OSM polling
- **XGBoost + SHAP** — optional ML upgrade path (rule-based classifier is the default)

## Setup

1. **Get a free FIRMS MAP_KEY**: https://firms.modaps.eosdis.nasa.gov/api/map_key/
2. Copy `.env.example` -> `.env`, fill in `FIRMS_MAP_KEY` and adjust `FIRMS_BBOX` / `OSM_BBOX`
   to your demo region (default is bounding all of India).
3. **Run with Docker (recommended)**:
   ```bash
   docker compose up --build
   ```
   This starts PostGIS + the API on `http://localhost:8000`. Tables + the
   PostGIS extension are created automatically on startup (`init_db()`).
   After first startup, apply the extra spatial indexes once:
   ```bash
   docker compose exec db psql -U thermal_user -d thermal_db -f /app/migrations/001_spatial_indexes.sql
   docker compose exec db psql -U thermal_user -d thermal_db -f /app/migrations/002_land_use_polygons.sql
   ```
4. **Or run locally** (needs a local PostGIS-enabled Postgres):
   ```bash
   pip install -r requirements.txt
   uvicorn app.main:app --reload
   ```

## First-time data load
```bash
# Pull industrial site polygons (Task #8)
curl -X POST http://localhost:8000/api/ingest/osm-refresh

# Pull FIRMS hotspots + run full classification pipeline (Steps 1-4)
curl -X POST http://localhost:8000/api/ingest/run
```

## Demo rehearsal (no live API key needed)
```bash
docker compose exec backend python -m scripts.seed_demo_data
```
Seeds a demo refinery with 25 days of steady "gas flare" readings, then one
sharp spike classified as `accident_explosion` — fires a `high`/`critical`
alert immediately, for a guaranteed on-stage "aha" moment.

## Notes on the classification approach
The default classifier (`app/services/classifier.py`) is a **rule-based
decision tree** over: z-score vs. that exact location's own history,
whether the point falls inside an industrial buffer (with a distance-based
confidence score, not a strict yes/no — per the "facility boundary doesn't
line up perfectly" risk in the problem statement), how many other hotspots
fired nearby on the same day, and land-use. This is intentionally simple
(Task #11: "any developer can do this") and always runs. `ml_classifier.py`
is a ready-to-train XGBoost+SHAP upgrade using the same feature set, kept
optional per Task #12 ("skip or simplify to rules if no one has ML background").
